# Issue

**Title:** ⚡ perf: cut the per-request cost of the extractors

## Description

# Description

The `extractors` package is what every middleware uses to pull a credential out of a request: keyauth's API key, CSRF's token, the session ID. It runs on every request of every app that uses those middlewares, and it was spending most of its time on bookkeeping rather than on reading the request.

Five changes, each measured on its own, make it **38% faster by geometric mean** and remove **11 allocations per request** from the paths that had them. Nothing about the public API moves, and no documented behavior changes.

The largest costs found and removed:

1. **Chain bookkeeping in request locals.** A chain kept its cycle guard, its capture depth and its winning source in separate `Locals` entries — four operations per `Chain.Extract` and five more per `ExtractWithSource`, each a linear scan of fasthttp's user values with interface equality, and every recorded winner allocated a fresh `[]Source` and boxed it. About 40% of a chain extraction was this. It is now one pooled `*chainState` under a single key, returned to its pool through `Close` when fasthttp resets the request.
2. **`App.Config()` copies 624 bytes to answer a boolean.** Every header extraction asks whether the store is normalized and whether `Immutable` promises the caller its own copy. Both answers cost a full copy of `Config`, measured at 25ns against 2ns for the `App()` call itself. A new `internal/appconfig` holds the three booleans that hot paths read, and package fiber installs the reader in its `init`.
3. **token68 validation scanned with range compares.** `FromAuthHeader` validated the credential after the scheme with a per-byte switch. A 256-entry table answers the same question with one indexed load.
4. **The non-normalized header path allocated three times per read.** Apps that keep the field names their peers sent — the lower-case spelling HTTP/2 and HTTP/3 put on the wire — went through a collector whose callback and result slice both escape. `Combined` now walks the header store itself for that case.
5. **The session store boxed a 72-byte `Extractor` per request.** A chain-configured store records which child supplied the ID so `Save` writes it back to the same place. It now records the address instead of the value.

One genuine bug surfaced while working on the session store and is fixed here in its own `): a chain containing a zero-value `Extractor` is well formed, and `Chain` skips such a child, but the session store walked the public chain itself and called every child straight through — crashing the request with a nil pointer dereference the first time it looked up a session ID.
